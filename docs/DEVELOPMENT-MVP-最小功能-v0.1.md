# 重置雷达：最小功能开发文档 v0.1

更新时间：2026-09-15  
状态：最小功能验证版

## 1. 这一版只验证什么

验证一个最核心假设：用户打开网页后，能否在 5 秒内知道“目前有没有公共 Reset 信号，以及未来 24 小时信号有多强”。

本轮只实现：

1. 从一份手动维护的数据读取状态。
2. 展示当前状态、24 小时信号分数和三条判断依据。
3. 对错误分数和未知状态进行兜底。
4. 用自动测试确认核心规则不会被改坏。

本轮不实现：

- 自动抓取社交媒体或官方公告。
- 邮件订阅和发送。
- 登录、付费、后台管理。
- 数据库、历史曲线和多模型支持。

## 2. 用户看到的最小页面

```text
当前状态：观察中 / 已确认 / 冷却期
24H 雷达：0—100 分
一句话结论
为什么分数变化：最多三条依据
数据更新时间与“演示数据”说明
```

页面优先级：状态 > 分数 > 原因 > 更新时间。不能先出现营销介绍再让用户寻找结果。

## 3. 数据源

第一版使用 `website/data/radar.ts` 作为唯一数据源。修改该文件并保存，页面就会更新。

字段说明：

| 字段 | 作用 | 示例 |
|---|---|---|
| `status` | 当前状态 | `watching` |
| `score` | 24 小时信号分数 | `75` |
| `updatedAt` | 数据更新时间 | ISO 时间 |
| `summary` | 一句话结论 | `还没重置，但信号正在升温。` |
| `reasons` | 判断依据，最多三条 | 员工信号、历史周期 |

允许的状态：

- `watching`：尚未确认，持续观察。
- `confirmed`：已有可信公共 Reset 证据。
- `cooldown`：刚发生 Reset，短期再次发生的可能性低。

## 4. 核心规则

1. 分数小于 0 时显示 0。
2. 分数大于 100 时显示 100。
3. 小数按四舍五入显示。
4. 未知状态回退到 `watching`，页面不能崩溃。
5. 时间无法解析时显示“更新时间未知”。
6. 页面必须明确说明当前是演示数据，避免被误认为实时情报。

## 5. 验收标准

- 首页无需点击即可看到状态和分数。
- 手机和桌面宽度均不产生横向滚动。
- 修改 `website/data/radar.ts` 后，页面内容随之变化。
- 自动测试覆盖分数上下限、四舍五入、风险分段和未知状态。
- `npm test` 与 `npm run build` 均通过。

## 6. 本地查看

进入 `website/` 目录后运行：

```bash
npm run dev
```

然后打开终端显示的本地网址。

运行功能测试：

```bash
npm test
```
