# Mac 自动监控 Tibo——MVP 运行手册

## 已确定的规则

- 每天北京时间 11:00 在站长的 Mac 上运行一次。
- 只读取 `@thsottiaux` 本人发布的公开帖子和回复。
- 明确宣布已经重置或发放重置卡时，自动更新网站。
- 只提到 usage、quota、limit 或 reset，但没有明确宣布结果时，不公开，发飞书等待站长决定。
- 普通帖子进入“Tibo 最近动态”。
- 不使用付费 X API、付费模型 API 或 GrokBot。
- 参考开源项目的分层方法重新实现，不直接复制其源码。

## 实际流程

```text
FxTwitter 公开 JSON
  → 校验 HTTP、JSON、作者、帖子 ID、时间与原帖链接
  → 过滤第三方对话上下文，只保留 Tibo 本人内容
  → 内容指纹去重，发现帖子修改时暂停自动更新
  → 明确重置：写入最近动态和重置公告
  → 普通帖子：只写入最近动态
  → 含糊帖子：写入 Mac 私有待审查队列并发送飞书
  → 数据检查、自动测试、正式构建
  → 只提交两个公开数据文件并推送 GitHub main
  → Vercel 按原有流程更新网站
```

网页不会显示提示词、运行日志、Webhook、错误堆栈或待审查队列。网页只显示最近核验时间、公开动态和已经确认的重置公告。

## 本地文件

私有运行状态都保存在：

```text
~/.reset-radar/
├── tibo-monitor-state.json   去重状态与待审查项目
├── tibo-monitor-audit.jsonl  每次运行的审计记录
├── feishu-webhook-url        飞书机器人地址，不进入 Git
└── logs/                     Mac 定时任务日志
```

仓库只会自动修改：

```text
website/data/tibo-posts.json
website/data/reset-feed.json
```

如果这两个文件已有未处理的本地修改，自动任务会停止并保留原状，避免覆盖人工工作。

## 先测试，再启用

在 `website` 目录运行：

```bash
npm run monitor:tibo
```

这是只读演练：读取真实公开数据、完成判断并输出审查摘要，但不改文件、不发飞书、不提交 GitHub。

确认演练正常后，可以运行一次“只更新本地、不推送”的完整检查：

```bash
npm run monitor:tibo:write
```

正式自动发布入口是：

```bash
npm run monitor:tibo:publish
```

它会先确认本地 `main` 与 GitHub `main` 完全一致，再执行检查、构建、提交和推送。任何一步失败都会停止发布并保留上一版网站数据。
为了避免“本地构建内容”和“GitHub 实际部署内容”不一致，正式发布时网站目录不能存在尚未提交的新文件，整个仓库也不能存在尚未提交的已跟踪修改。

## 配置飞书

1. 在飞书群里添加“自定义机器人”，复制 Webhook 地址。
2. 不要把地址发送到聊天或提交 GitHub。
3. 在 Mac 上复制该地址，然后进入 `website` 目录运行：

```bash
npm run monitor:feishu:configure
```

脚本只从 Mac 剪贴板读取并保存到私有文件。未配置飞书时，巡检仍然可以运行，但报告只保存在本机。

## 安装每天 11:00、15:00、21:00 的任务

先预览将要安装的配置：

```bash
node scripts/install-tibo-monitor.mjs --dry-run
```

验收通过后安装：

```bash
npm run monitor:tibo:install
```

安装后由 macOS `launchd` 每天 11:00、15:00、21:00 执行自动发布。Mac 关机时无法运行；睡眠期间错过的任务通常会在唤醒后补跑，但不能承诺准点。

如需停用：

```bash
npm run monitor:tibo:uninstall
```

## 失败保护

- 上游非 200、返回非 JSON、字段异常：判为失败，不当成“没有新帖子”。
- 第三方上下文：过滤，不冒充 Tibo 的帖子。
- 同一帖子：内容指纹去重。
- 已处理帖子发生修改：暂停并交给人工确认。
- 含糊语义：不公开，安全默认动作是保持现状。
- 数据校验、测试或构建失败：恢复两个公开数据文件。
- 本地与 GitHub 不一致：不自动拉取、不覆盖，直接提醒人工处理。
- 重复任务：使用单实例锁，避免同时运行两次。

## 当前限制

- 免费 FxTwitter 接口是第三方服务，没有可用性承诺。
- 每天只运行一次，11:00 后的新公告最晚可能到次日才发现。
- Mac 必须能够联网，并且项目目录、Node.js 与 GitHub SSH 登录保持可用。
- 第一次正式启用前建议连续做 3—7 天只读演练，核对漏帖和误判。
