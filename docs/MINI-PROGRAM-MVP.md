# 网站与既有小程序：本机 MVP

验收日期：2026-09-29。范围：本机数据通路，不是线上切换或新采集系统。

## 唯一数据路径

旧站已公开快照（现有采集、审核的发布出口）
→ 手动运行一次同步
→ 校验字段、数量、引用和撤回记录
→ 单次数据库写入，同时更新网站视图和小程序完整快照
→ 新网站页面 / 既有小程序同步模块读取。

- 上游固定为 https://www.resetrelay.com/api/public/v1/snapshot；禁止跳转，10 秒超时，1 MB 限制。
- 本机接口：http://localhost:3210/api/public/v1/snapshot
- 页面：http://localhost:3210/monitor/codex
- 保留原始核验时间；导入时间不代表核验时间。
- 不把 signal 改成 full，不自动推断重置完成。
- 新接口只允许读取；写入入口是本机脚本，不对互联网开放。
- 数据不完整、字段不兼容或网络失败时，不覆盖已有发布内容。
- 发布字段为白名单，案例只保留摘要与问题，不复制导入的 quotes。
- 内容修订生成新版本；相同内容返回 304；撤回在同次发布中从两端移除。

## 本机复跑

在新网站目录运行：

```sh
node scripts/local-preview.ts
```

另一个终端执行一次：

```sh
node scripts/sync-reset-local.ts
```

同步脚本只读取本机预览凭据，并将数据库地址固定到本机预览库，不读取生产数据库配置。
不需要将数据库凭据、微信 AppSecret 或其他密钥填写到小程序中。

在既有「重置雷达小程序」项目运行：

```sh
node scripts/test-sync-integration.cjs http://localhost:3210/api/public/v1/snapshot
npm test
npm run check
```

该联调使用真实的小程序 feed 模块，只替换请求地址和微信存储适配器，不修改小程序默认生产地址。
验收应看到首次 200、第二次 304、cacheRecovery=true、offlineRetention=true。
这不是微信真机测试；localhost 不能直接给用户手机使用。

## 尚未启用

本轮没有配置自动定时任务、直接抓取 X、付费 API、飞书推送、微信订阅通知或管理后台按钮。
当前是“已有发布源 → 手动触发一次 → 两端兼容读取”的最小闭环。
后续上线前需确认：生产承载位置、HTTPS 域名与微信白名单、发布审批、失败告警与真机验收。
不要先移除旧站出口：它目前仍是生产小程序的数据源。
新接口遇到尚未支持的事件类型会拒绝整次导入并保留旧数据，不能静默跳过。
