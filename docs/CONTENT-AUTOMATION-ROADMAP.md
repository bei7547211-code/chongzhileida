# 重置雷达：内容自动化开发计划

保存日期：2026-10-02（北京时间）
来源：用户本轮确认的开发顺序。
状态：顺序已确认；功能待分阶段实施及验收，不代表已经上线。

## 固定顺序

统一内容库 → 自动采集与失败重试 → 精选和主题 → 日报 → 热度排名。

目标：一篇真实资讯被采集后，进入统一内容库，展示在正确的栏目和主题中，进入当天日报；重复、失败、更正、撤回均可追踪。
范围：AI 行业官方博客、产品更新、技术媒体。继续保留重置公告的独立事实核验边界。

## 1. 统一内容库

- 优先复用 AIHOT 的来源、内容、发布层，不再扩展独立资讯孤岛。
- 将当前 RSS 短摘要接入统一内容模型，保留来源 URL、原始时间、采集时间、语言、处理状态和版本。
- 不将未经筛选的 RSS 原文自动标成“精选”；不把普通 AI 新闻写成重置公告。
- 网站、内容 API、RSS 等出口从同一发布层读取；兼容现有小程序快照协议。
- 做增量迁移和回滚方案，保留现有数据，先在隔离库演练。
- 验收：相同内容只入库一次；列表、详情及 API 一致；更正和撤回能同步生效。

## 2. 自动采集与失败重试

- 复用已有后台任务、去重及请求保护；先手动跑通，再接入调度。
- 每个来源记录最后尝试、最后成功、失败原因、下次重试；有限重试并退避，避免持续轰炸源站。
- 单来源失败不阻塞其他来源、不清空已有内容；旧内容明确显示时间。
- 区分旧站监控任务与新站采集任务，避免重复发布。
- 验收：模拟超时、坏 XML、限流及进程中断，恢复后无漏处理和重复发布。
- 启用前确认运行位置、频率、预算、通知接收方；不沿用旧站时间作为新资讯的默认授权。

## 3. 精选和主题

- 先接通全部资讯、来源分类与主题归档，再按可解释标准筛选精选。
- 保留底座现有评分结构；门槛用用户标注样本校准，不凭空设分数。
- 原文、译文、摘要分开保存；中文加工不得增加未经来源支持的事实。
- 验收：主题与精选都有真实内容，筛选依据可查；不符合标准的内容只进入普通资讯。

## 4. 日报

- 从统一发布内容生成带原文链接的日报，按北京时间划分日期。
- 没有新内容不伪造日报；失败可补跑，同一天重复运行不重复发布。
- 未实际启用前，不展示“每天固定时间发布”的运营承诺。
- 验收：真实资讯进入当日日报，历史归档可查，补跑与更正能保持一致。

## 5. 热度排名

- 合并同一事件的多来源报道，按独立来源和时间衰减计算热度。
- 重复采集、同源转载不能重复抬高热度；缺少历史不伪造趋势。
- 当前最新资讯列表和真正的热榜必须明确区分。
- 验收：可追溯组成热度的来源；新增独立来源、时间推移和撤回会正确影响排名。

## 每阶段交付门槛

1. 类型检查、构建、隔离库测试通过。
2. 正常、空数据、异常接口、重试、撤回测试通过。
3. 浏览器直接打开、站内切换、手机宽度均验收。
4. 文档分别记录“已开发、已验证、已启用、已部署”，不混为一谈。
5. 不提交密钥、本地数据库、缓存或私有素材；保留 MIT 许可及必要归属。
